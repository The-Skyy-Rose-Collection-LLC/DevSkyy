SkyyRose Flagship 2 / source verification

WordPress, simplified around the house.

A code-backed record of what V2 now does, what was removed, what passed locally, and what still requires an installed archive on WordPress/WooCommerce staging.

HOLD
Source blockers identified in this audit were corrected, but marketplace release is not certified.
Static checks cannot replace real product, cart, checkout, builder, accessibility, visual, and performance tests against the exact packaged archive.

Outcome

Theme identity

V2 is a classic WordPress/WooCommerce theme with protected SkyyRose collection worlds—not an interchangeable page skin.

Version

Source version advanced from 2.3.4 to 2.3.5 because PHP, CSS, JavaScript, and public behavior changed.

Commerce truth

WooCommerce remains authoritative for names, images, SKU resolution, visibility, stock, price, product URL, variations, and pre-order categorization.

Builder boundary

Gutenberg and supported builders may own page content. The theme retains WooCommerce and protected collection fallbacks unless an official Elementor Pro location is assigned.

Brand boundary

The continuous rotating mark remains the house header asset. WordPress-configured primary and footer menus now work with branded route fallbacks.

3D boundary

Product 3D remains fail-closed through the approved local GLB manifest. Raw Divi custom-element allow-listing was removed.

Simplified WordPress contract

Theme owns

  • House header/footer fallback and rotating brand mark.
  • Four protected collection identities and narrative surfaces.
  • Shared semantic product-card system.
  • Responsive SOT campaign media.
  • Fail-closed approved-model 3D resolver.
  • Builder canvas/full-width templates and official location handoff.

WordPress/WooCommerce owns

  • Page content and configured navigation menus.
  • Product names, SKUs, visibility, images, price, stock, variations, and categories.
  • Cart, checkout, tax, shipping, payment, order, and account state.
  • Standard product-loop extension hooks.
  • Administrator configuration for the approved muted About film URL.

This is the key simplification: builders compose pages; WooCommerce controls commerce truth; SkyyRose controls the house. No layer is allowed to impersonate another.

Release closeout still required

  1. Commit the scoped 2.3.5 source, build the archive from that immutable commit, and verify its digest and contents.
  2. Install that exact archive on the named staging WordPress site with WooCommerce active.
  3. Verify home, collections index, all four collection worlds, pre-order, About, Contact, shop, product types, cart, coupon, tax, shipping, payment, receipt, account, search, empty, and 404 states.
  4. Repeat builder ownership checks with the exact Gutenberg/Elementor/Divi/Beaver versions advertised.
  5. Run desktop/mobile browser, keyboard, screen-reader spot checks, automated accessibility, Lighthouse/performance trace, responsive, and visual/SOT comparison.
  6. Run Theme Check, WPCS, and PHPStan with declared marketplace tooling.
  7. Complete the rights ledger for every distributed asset and sign founder, build-attestor, and policy-collector evidence over the final package digest.

Decision

V2 is materially cleaner and more truthful, but it remains a release candidate—not a marketplace release. The next valid action is archive-bound staging verification. Adding more spectacle before those flows pass would increase risk without proving commerce quality.
